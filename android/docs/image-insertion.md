# Image insertion at the captured cursor — 2026-10-08

Swift importImages captures a document/selection snapshot, rejects changed drafts and calls PostDraftDocument.insertingImages at the selection start. Android previously appended every attachment marker after the complete body. PostComposer now captures the selection start and uses the same insertion/order/newline rule, retaining selected text and the existing trailing body. New posts, replies and edits share this path.

The saveable ticket contains scope/body SHA-256 fingerprints and a UTF-16 offset, without another saved copy of the body or image bytes. Scope includes the canister, owner, parent and edit ID. The callback consumes the ticket once; cancellation does not insert anything. It waits up to 30 seconds for draft/old-image loading, checks the live owner and body before import and again before saving, and asks the user to choose images again on mismatch. Imported DraftImage bytes remain transient until the successful existing saveImages path. The editor consumes a one-time selection request so later typing is not forced back to the insertion point.

Three JVM cases cover ticket string restoration, owner/body changes and malformed tickets, selected-text preservation, multiple-marker order, empty/image lines and Unicode UTF-16 positions. An additional native editor case uses a real selection, applies image-marker insertion and types at the resulting caret, verifying the request is consumed and the trailing character remains. Existing editor/repost/reply/video-owner cases are retained as regression checks.

These checks are algorithm and native-editor integration evidence. They do not establish real OS photo-picker selection, permission restoration, process death during import or an authenticated normal-app upload using the new cursor path. The earlier normal-app image upload evidence used the previous append behavior. Those stronger journeys remain separate requirements.

Debug/Release each pass 260 JVM cases, both Lint tasks and all public app/test/unsigned Release builds. Evidence is under ignored .build/android: image-insertion-final-build.log, image-insertion-release-artifact-audit.json and associated manifest/signature/configuration files. No signing, deployment, real-account authorization or production mutation occurred.
