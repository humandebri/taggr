# Markdown editing toward Swift — 2026-10-08

Swift ComposePostAttachmentBar and ComposeMarkdownEdit provide Bold, Italic, Bullet list, Quote and Link operations over the current UTF-16 selection. Android PostComposer previously exposed a plain String field with preview and attachments, without these actions. MarkdownEditor now provides the five actions using TextFieldValue selection, a horizontally scrollable toolbar and a Link URL dialog. Bold/italic preserve the selected interior; list prefixes each selected line, quote prefixes the selection, and link inserts the selected label or an empty editable label. Surrounding text remains intact.

New posts, replies and editing share this editor. Text changes use the existing owner/parent/edit-scoped saveDraft path. The editor is keyed by that same context, preserves saveable selection and clamps it when an external draft changes. Existing upload-completion and image attachment paths remain the source of external body changes. Link insertion requires the draft still to equal its captured snapshot and the editor still to be enabled; cancellation retains the body. No post is automatically submitted by formatting.

Two JVM cases cover Unicode/surrogate-pair selection, an empty caret, reversed selection, multiline list/quote/link transformations and surrounding text. Two native cases exercise actual selection and toolbar/dialog controls, callback retention, cancellation/insertion and rejection of a stale snapshot after replacement. Existing inline reply and completed-video insertion cases provide targeted regression coverage. These do not establish normal signed-user process-death selection restoration, complete iOS undo behavior or attachment insertion at the cursor. Repost integration is recorded below; other separately implemented fields require their own scope review.

Formatting remains disabled while busy or while the outcome of the previous request is unknown.
